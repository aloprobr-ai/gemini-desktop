# Gemini Desktop

Настольный клиент Gemini для Windows: чаты, картинки, свои промты, работа
с файлами и команды.

Приложение работает через любой шлюз, совместимый с OpenAI API: например,
[agy-gateway](https://github.com/aloprobr-ai/agy-gateway) на этом же
компьютере, чужой шлюз или Google Gemini API по вашему ключу. Адрес
указывается при первом запуске и меняется в настройках.

Переписка и ключ хранятся на вашем компьютере. Ключ не показывается ни
в интерфейсе, ни в логах, ни в текстах ошибок.

## Что умеет

* **Чаты**: список слева, поиск, закрепление, переименование, удаление.
  Каждый чат хранится в отдельном файле.
* **Картинки**: кнопкой, перетаскиванием или вставкой из буфера. Картинки,
  нарисованные моделью, показываются в ответе.
* **Свои промты**: общий и для инструментов, у каждого есть кнопка «Сбросить».
* **Команды**: `/human`, `/check`, `/compact` и `/agy` (если шлюз разрешил).
  Список появляется, если набрать «/».
* **Проверка текста**: после `/human` текст проверяется детектором ИИ-текста.
  Подозрительные места подсвечиваются, текст можно переписать ещё раз
  с учётом замечаний. `/check` проверяет любой текст без переписывания.
* **Выгрузка**: один чат или все чаты в Markdown.
* **Файлы**: модель может создавать, читать и открывать файлы, а также писать
  себе новые инструменты. Новый инструмент запускается только после того, как
  вы посмотрели код и разрешили.
* **Трей**: окно сворачивается в значок, приложение продолжает работать.
  О готовом ответе приходит уведомление Windows.
* **Отчёт об ошибке**: кнопка под ответом и в настройках, отчёт отправляется
  автору в Telegram.
* **Обновления**: из выпусков GitHub, с проверкой контрольной суммы.
* **Тема**: светлая и тёмная.

## Установка

Скачайте `GeminiDesktop-*.msi` со [страницы выпусков](https://github.com/aloprobr-ai/gemini-desktop/releases)
и запустите. Установщик спросит про ярлык на рабочем столе и автозапуск.
При обновлении вопросов нет, работающая копия закрывается автоматически.

Нужен Microsoft Edge WebView2. В Windows 11 он уже установлен, если его нет,
установщик подскажет, где взять.

Программа ставится в `Program Files`, поэтому нужны права администратора.
Настройки и переписка у каждого пользователя свои и при удалении программы
не удаляются.

## Первый запуск

Мастер спросит адрес шлюза и ключ. По умолчанию стоит
`http://127.0.0.1:8080/v1`, то есть [agy-gateway](https://github.com/aloprobr-ai/agy-gateway)
на этом же компьютере. Если шлюз работает без ключа, поле можно оставить
пустым.

Перед тем как пустить дальше, мастер запрашивает `/models`. Если шлюз
не ответил, мастер покажет ошибку.

## Окно

Слева чаты, сверху выбор модели, уровня размышлений и переключатель
инструментов, снизу строка ввода.

Крестик сворачивает окно в трей, ответ при этом продолжает приходить.
Выйти из программы можно через меню значка.

Запущена всегда одна копия. Если открыть ярлык ещё раз, появится окно уже
работающей программы.

## Чаты

Каждый чат хранится в отдельном файле в `%APPDATA%\GeminiDesktop\chats`.
При запуске читаются только названия, сам чат загружается при открытии,
поэтому большое число чатов не замедляет запуск.

* **Поиск**: Ctrl+F, по названиям.
* **Закрепление**: закреплённые чаты показываются отдельной группой сверху.
* **Переименование, выгрузка и удаление**: кнопки появляются при наведении.
* **Название** задаётся по первому сообщению. Для команды берётся её текст,
  а не «/human».

## Картинки

Картинку можно приложить кнопкой-скрепкой, перетащить в окно или вставить
из буфера (Ctrl+V). Миниатюры появляются над строкой ввода, лишние можно
убрать до отправки.

За раз можно отправить не больше четырёх картинок, у каждой есть предел
размера. Картинки хранятся в файле чата целиком, без ограничения файл
быстро разрастается до десятков мегабайт.

Картинку, нарисованную моделью, можно сохранить из ответа.

## Команды

Наберите «/», чтобы открыть список. Стрелки выбирают команду, Enter или Tab
подставляют, Escape закрывает список. В окне остаётся то, что вы набрали,
а модели уходит полный запрос команды.

### `/human [текст]`

Переписывает текст так, чтобы он читался как написанный человеком. В запросе
к модели описано, что убирать: пустые вступления и концовки, слова-паразиты,
канцелярит, штампы, перечисления по три, одинаковые начала абзацев, цепочки
родительных падежей, пафос. Отдельно задан ритм: средняя длина предложения
11–14 слов при разбросе от 2 до 35, хотя бы одно короткое на каждые 6–8,
абзацы разной длины.

Без текста берётся последний ответ модели.

Факты команда не придумывает. Там, где нужна деталь, которой нет в исходном
тексте, ставится метка `[нужна деталь: какая именно]`, в конце ответа такие
метки собраны списком. Намеренных опечаток тоже нет.

Если в `settings.json` заполнить `styleSample` (200–600 слов вашего текста),
модель будет подстраиваться под ваш стиль. Поля для этого в окне настроек
пока нет.

### Проверка после `/human`

Запускается сама после ответа на `/human` и показывает результат под ним.

Оценок две, в одно число они не сводятся:

* **по признакам**: пятнадцать измеримых величин (ритм, штампы, канцелярит,
  конкретика, списки, заголовки). Считаются на компьютере, без сети;
* **по мнению модели**: модель хорошо узнаёт стиль, но аккуратный
  человеческий текст часто принимает за машинный.

Модель спрашивается три раза, чтобы был виден разброс оценок. Если разброс
большой или оценки не совпадают, это будет указано.

Проверяется только переписанный текст. Служебная часть ответа (метки
`[нужна деталь]`, список убранного, примеры фраз) отрезается, иначе детектор
оценивал бы её.

Настройки в разделе «Проверка текста после /human»: проверку можно
выключить, число запросов задать от 1 до 5, модель-судью выбрать свою.
По умолчанию это `gemini-3.1-pro-high`: у быстрых моделей оценки сильнее
разбегаются от запроса к запросу.

Фразы, которые судья посчитал машинными, подсвечиваются в тексте ответа,
при наведении видно пояснение. Если судья процитировал фразу неточно или она
разорвана разметкой, подсветки не будет, но в итогах проверки она есть.

**Переписать ещё раз по замечаниям.** Если итог хуже «не берусь сказать»,
появляется эта кнопка. К новому запросу `/human` добавляются найденные
проверкой фразы и признаки, чтобы модель исправила именно их. Новый ответ
проверяется так же.

Результат проверки не окончательный. Короткий текст не оценивается, об этом
будет написано. Текст, скопированный из интернета, написан человеком, но
часто получает машинную оценку по обоим показателям.

Детектор лежит в папке `detector/`. Это копия отдельного проекта ai-detector,
чтобы сборка не зависела от других папок на компьютере.

### `/check [текст]`

Проверяет текст тем же детектором, что и после `/human`, но не переписывает
его. Подходит для чужого текста, своего черновика или повторной проверки
с другой моделью-судьёй.

Без текста берётся последний ответ модели. Если это был ответ на `/human`,
проверяется только переписанный текст.

Команда и её результат в историю разговора не попадают. Кнопка
«Перегенерировать» запускает проверку заново. Если текст не прошёл
проверку, его можно сразу отправить на `/human` с замечаниями.

### `/compact [на что обратить внимание]`

Сворачивает разговор в сводку: тема, принятые решения и причины, что
сделано, что выяснилось, договорённости и где остановились. Имена, пути
и фрагменты кода переносятся дословно.

После этого модель видит только сводку. Старые сообщения остаются в чате,
место свёртки отмечено чертой.

Можно указать, на чём сосредоточиться: `/compact особенно про шлюз`.

### `/agy on|off`

Включает и выключает промт agy на шлюзе [agy-gateway](https://github.com/aloprobr-ai/agy-gateway)
для вашего ключа. agy добавляет к каждому запросу свой промт агента на
десятки тысяч знаков. Шлюз с перехватчиком может его убрать, тогда отвечает
обычный Gemini.

| Команда | Что делает |
|---|---|
| `/agy` | показывает текущее состояние |
| `/agy off` (`выкл`) | убрать промт agy |
| `/agy on` (`вкл`) | вернуть промт agy |

**Команда доступна, только если владелец шлюза разрешил её для вашего
ключа** командой `agy-prompt on all` или `agy-prompt on <ключ>` на сервере.
Приложение проверяет это при запуске и после сохранения настроек. Без
разрешения команды нет в списке, а текст «/agy …» уходит модели как обычное
сообщение. Если разрешение отозвали, пока приложение открыто, следующая
`/agy` сообщит об этом и команда пропадёт.

Ответ на `/agy` приходит от шлюза и в историю разговора не попадает.

## Инструменты

Переключатель в шапке включает и выключает все инструменты сразу.

Встроенные:

| Инструмент | Что делает |
|---|---|
| создать файл | txt, md, csv, json или log, по умолчанию в «Загрузки» |
| прочитать файл | только текстовые форматы |
| открыть папку | показывает файл в проводнике |
| написать инструмент | модель пишет новый инструмент, он ждёт вашего разрешения |

Файлы `.exe`, `.bat` и подобные по запросу модели не создаются: расширение
заменяется на `.txt`.

Папка программы `%APPDATA%\GeminiDesktop` для инструментов закрыта: модель
не может ни писать туда, ни читать оттуда. Там лежат ключи, чаты и отметки
о разрешённых инструментах, и иначе модель могла бы сама разрешить свой
инструмент или подменить адрес обновлений.

Инструмент, написанный моделью, сам не запускается. Сначала показывается
его код, работать он начнёт после нажатия «Разрешить». Модель читает файлы
и страницы, и в них может оказаться текст, который подтолкнёт её написать
что-то вредное.

Разрешённые инструменты, их код и кнопка удаления находятся в настройках,
раздел «Инструменты, написанные моделью».

## Модель и уровень размышлений

Шлюз отдаёт около пятнадцати имён, но многие из них одна модель с разным
уровнем размышлений: `gemini-3.7-flash-low`, `-medium`, `-high`. Поэтому
в списке только модели, а уровень выбирается отдельным переключателем.
Если у модели уровней нет, переключатель скрыт.

Псевдонимы (`agy`, `gpt-4o` и другие) из списка убраны, они ведут на те же
модели. Сохранённый раньше псевдоним при запуске заменяется настоящим именем.

Модель запоминается для каждого чата.

## Сообщить о баге

Кнопка с жучком есть под каждым ответом рядом с «Копировать»
и «Перегенерировать», а также в настройках, раздел «Обратная связь».

Кнопка копирует отчёт в буфер обмена и открывает чат с автором в Telegram
([@lisemicki](https://t.me/lisemicki)). Текст также подставляется в поле
ввода (`t.me/<ник>?text=…`), но не все клиенты Telegram это поддерживают,
поэтому отчёт всегда есть и в буфере.

Сервера-посредника и токена бота в программе нет: токен в открытом исходном
коде могли бы использовать посторонние.

Отчёты не публикуются задачами в репозитории, потому что в описании ошибки
бывает написано, как сломать программу. Задачи в репозитории можно
создавать вручную.

Содержимое отчёта выбирается галочками: версия и система, последние строки
журнала запуска, один ответ модели. Переписка целиком не отправляется.
Ключи из отчёта удаляются, от адреса шлюза остаётся только имя хоста.
Кнопка «Показать, что уйдёт» показывает отчёт до отправки.

## Кто помог проекту

Список в [Helpers.md](Helpers.md), на него есть кнопка в настройках.

Чтобы попасть в список, отметьте в окне отчёта «Подпись в Helpers.md»
и укажите имя и ссылку. Если по отчёту что-то исправят, подпись добавят
в файл.

Галочку нужно ставить каждый раз, хотя имя и ссылка запоминаются. Скобки
из подписи удаляются, ссылка принимается только с `http://` или `https://`,
чтобы подпись не ломала разметку файла.

## Выгрузка чатов

Один чат выгружается кнопкой со стрелкой в списке чатов: откроется окно
сохранения, после сохранения файл покажется в проводнике. Все чаты сразу
выгружаются в настройках, раздел «Выгрузка»: в выбранной папке создаётся
новая, с отдельным файлом на каждый чат.

В файл попадает то же, что видно в окне: сообщения, ответы, действия
инструментов, результаты проверок, ошибки и место свёртки. Полные запросы
команд не сохраняются, вместо них «/human текст». Картинки не сохраняются,
вместо них указано их количество.

## Настройки

| Раздел | Что внутри |
|---|---|
| Подключение | Провайдер, адрес шлюза, ключ, кнопки «Удалить» и «Проверить» |
| Промты | Общий промт и промт инструментов |
| Проверка текста после /human | Включение, число запросов, модель-судья |
| Файлы | Папка по умолчанию для новых файлов |
| Инструменты, написанные моделью | Код, разрешение и удаление |
| Расход | Запросы и токены за сегодня и за месяц, если шлюз их отдаёт |
| Запуск | Автозапуск вместе с Windows, свёрнутым в трей |
| Выгрузка | Все чаты в Markdown, по файлу на чат |
| Данные | Где лежат чаты, кнопка «Удалить все чаты» |
| Обратная связь | Кнопка «Сообщить о баге» |
| Кто помог проекту | Ссылка на Helpers.md |
| О программе | Версия и проверка обновлений |

Некоторые настройки есть только в `settings.json`: `temperature`,
`maxTokens`, `streaming`, `showThoughts`, `proxy` (HTTP или SOCKS5),
`styleSample` и `updateUrl`. Источник обновлений и прокси вынесены туда,
чтобы их нельзя было поменять случайно.

## Где что лежит

```
%APPDATA%\GeminiDesktop\
  settings.json      настройки и ключ
  index.json         список чатов: названия, время, закрепление
  chats\<id>.json    переписка, по файлу на чат
  tools\             инструменты, написанные моделью
  boot.log           журнал запуска
```

При удалении программы папка остаётся. Удалить переписку без настроек можно
кнопкой «Удалить все чаты».

## Что уходит наружу, а что нет

**На шлюз, который вы указали:** сообщения, картинки, промты и история чата
(после `/compact` только сводка и то, что после неё).

**На шлюз при проверке:** текст, который проверяется после `/human` или
командой `/check`.

**На шлюз для `/agy`:** запрос разрешения при запуске и после сохранения
настроек, сами команды `/agy`. Содержимое чатов не отправляется.

**На GitHub:** проверка новой версии раз за запуск и скачивание установщика,
если вы согласились обновиться.

**В Telegram:** только отчёт об ошибке, после нажатия кнопки, в объёме,
отмеченном галочками.

**Никуда:** ключ (хранится на компьютере и удаляется из логов и текстов
ошибок), переписка, имена ваших файлов и папок.

Оценка по признакам считается на компьютере, а оценка модели отправляется
на шлюз вместе с текстом.

## Обновления

При каждом запуске приложение проверяет выпуски на GitHub и предлагает
обновиться. Черновики и предварительные выпуски не учитываются.

Скачанный установщик сверяется с контрольной суммой из файла `*.msi.sha256`
в выпуске. Если сумма не совпала, установка не начнётся. Если файла с суммой
нет, установщик ставится без проверки.

Чтобы брать обновления из другого места, добавьте в `settings.json`:

```json
"updateUrl": "https://ваш.шлюз/up"
```

## Сборка из исходников

Выпуски собирает GitHub Actions (`.github/workflows/release.yml`). Порядок:
поднять `APP_VERSION` в `app.py`, закоммитить, поставить тег `vX.Y.Z`
и отправить его. Сборка запустит проверки, соберёт exe и MSI, посчитает
контрольную сумму и создаст черновик выпуска. Пользователи получат
обновление после публикации выпуска. Если тег не совпадает с `APP_VERSION`,
сборка остановится.

Локальная сборка, нужны Python 3.11+ и Windows:

```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt pyinstaller
.venv\Scripts\python.exe app.py
```

Сборка exe:

```powershell
.venv\Scripts\pyinstaller.exe --noconfirm "Gemini Desktop.spec"
```

Собирайте интерпретатором из `.venv`. В системном Python обычно нет
`pywebview`, и PyInstaller соберёт exe без него: файл будет меньше обычного
(около 16 МБ вместо ~20) и при запуске ничего не покажет.

Сборка установщика (нужен [WiX 6](https://wixtoolset.org/)):

```powershell
powershell -File installer\build_msi.ps1
```

Версия берётся из `APP_VERSION` в `app.py`. Скрипт выводит контрольную
сумму, её нужно приложить к выпуску файлом `GeminiDesktop-<версия>.msi.sha256`.

`make_icon.py` пересобирает `icon.ico` из `assets/spark.png`.

## Проверки

Работают без сети и запускаются на GitHub при каждом push
(`.github/workflows/tests.yml`):

```powershell
.venv\Scripts\python.exe tests\test_commands.py
.venv\Scripts\python.exe tests\test_check_report.py
.venv\Scripts\python.exe tests\test_check_export.py
.venv\Scripts\python.exe tests\test_agy_cmd.py
.venv\Scripts\python.exe tests\test_tool_guard.py
```

* `test_commands`: разбор команд, свёртка, сборка истории для обоих бэкендов.
* `test_check_report`: детектор, отрезание служебной части, удаление ключей
  из отчёта, подпись для Helpers.md, адрес отчёта. Судья и браузер заменены
  заглушками.
* `test_check_export`: `/check`, замечания для повторного `/human`, выгрузка
  в Markdown.
* `test_agy_cmd`: `/agy` без разрешения и с ним, отзыв разрешения. Шлюз
  поддельный, запускается в том же процессе.
* `test_tool_guard`: инструменты модели не пишут и не читают в папке
  программы, в том числе через короткие имена, `\\?\` и `\\localhost\c$`.

Файлы с приставкой `live_` в папке `tests` обращаются к настоящему шлюзу
и запускаются вручную.

## Как устроено

```
app.py            бэкенд: запросы к шлюзу, инструменты, хранилище, мост в JS
detector/         детектор ИИ-текста: признаки, оценка, запрос к судье
ui/index.html     разметка окна
ui/style.css      оформление
ui/app.js         интерфейс: чаты, настройки, вложения, обновления
installer/        WiX-описание установщика и скрипт сборки
tests/            проверки без сети и с сетью
.github/workflows/ проверки на каждый push и сборка выпуска по тегу
requirements.txt  зависимости
make_icon.py      сборка иконки
assets/           исходник иконки
Helpers.md        кто помог проекту
```

Python и интерфейс связаны через мост pywebview: JS вызывает методы класса
`Api`, Python отправляет события обратно. Окно хранится только в поле
с подчёркиванием (`api._window`): при старте pywebview обходит поля `js_api`,
и обычное поле с окном вешает запуск.

Бэкендов два: `OpenAIBackend` для OpenAI-совместимых шлюзов и `GoogleBackend`
для Google напрямую. Оба отдают ответ потоком, размышления отдельно от
текста, вызовы инструментов списком.

Модель вызывает инструменты двумя способами: через `tool_calls` или через
текстовый протокол. Текстовый нужен, потому что в потоковом режиме шлюз
не всегда отдаёт `tool_calls`.

Одна копия приложения обеспечивается именованным мьютексом. Вторая копия
находит мьютекс, обращается к сокету первой, та показывает окно, а вторая
завершается. Файл с номером порта для этого не подходит: при одновременном
запуске две копии не видят друг друга.

## Если что-то не работает

**Окно белое или не открывается.** Не установлен WebView2. Установите его
с сайта Microsoft и запустите программу снова.

**«Укажите API-ключ в настройках».** Выбран провайдер `google`, а ключ
вписан в поле шлюза, или наоборот. Ключи хранятся отдельно.

**Список моделей пуст.** Нажмите «Проверить» в настройках, там будет ответ
шлюза. Писать можно и с пустым списком, тогда используется модель
по умолчанию.

**Шлюз работает, а ответа нет.** Посмотрите `boot.log`, там время запуска,
моста и запроса моделей.

**Проверка после `/human` пишет, что судья не ответил.** Проверка использует
тот же шлюз, но отдельный запрос без потока. Если чат работает, а проверка
нет, скорее всего, выбранной модели-судьи на шлюзе нет. Смените её
в настройках или очистите поле.

**Обновление не находится.** Проверяются только опубликованные выпуски
GitHub. Если их нет, приложение сообщит, что версия последняя.
