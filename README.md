# Gemini Desktop

Настольный клиент Gemini для Windows: чаты, картинки, свои промты и файлы —
всё в обычном окне, без браузера.

Приложение само по себе к Google не ходит. Оно разговаривает с любым шлюзом,
совместимым с OpenAI API, — подойдёт [agy-gateway](https://github.com/aloprobr-ai/agy-gateway),
поднятый на этом же компьютере, чужой шлюз или Google Gemini API напрямую
по вашему ключу. Адрес вы указываете при первом запуске.

## Что умеет

- **Чаты** — список слева, переименование, удаление; переписка лежит в файлах
  на вашем компьютере и никуда не уходит.
- **Картинки** — можно приложить кнопкой, перетащить в окно или вставить из
  буфера. Картинки, нарисованные моделью, показываются прямо в ответе.
- **Свои промты** — общий и отдельный для инструментов.
- **Файлы** — модель умеет создавать, читать и открывать файлы на вашем
  компьютере. Свои инструменты она тоже умеет дописывать, но запускаются они
  только после того, как вы разрешите.
- **Значок в трее** — окно прячется, приложение продолжает работать.
  О готовом ответе сообщит уведомление Windows.
- **Обновления** — проверяются в выпусках GitHub, ставятся одной кнопкой.

## Установка

Скачайте `GeminiDesktop-*.msi` со [страницы выпусков](https://github.com/aloprobr-ai/gemini-desktop/releases)
и запустите. Установщик спросит про ярлык на рабочем столе и запуск вместе
с Windows; при обновлении он ничего не переспрашивает и сам закрывает
работающую копию.

Нужен Microsoft Edge WebView2 — в Windows 11 он уже есть. Если нет,
установщик скажет, откуда его взять.

### Первый запуск

Мастер спросит адрес шлюза и ключ. По умолчанию подставлен
`http://127.0.0.1:8080/v1` — это [agy-gateway](https://github.com/aloprobr-ai/agy-gateway)
на этом же компьютере. Если ваш шлюз не требует ключа, поле ключа можно
оставить пустым.

Настройки и переписка хранятся в `%APPDATA%\GeminiDesktop`. При удалении
программы они остаются на месте.

## Настройки

| Раздел | Что внутри |
|---|---|
| Подключение | Провайдер, адрес шлюза, ключ, кнопка «Проверить» |
| Промты | Слева — общий промт, справа — промт инструментов |
| Файлы | Папка по умолчанию для создаваемых файлов |
| Генерация | Температура, лимит токенов, стриминг, показ размышлений |
| Сеть | HTTP- или SOCKS5-прокси |
| Инструменты | Что модель написала сама; запуск — только с вашего разрешения |
| О программе | Версия и проверка обновления |

## Модель и уровень размышлений

Шлюз отдаёт около полутора десятков имён, но это одни и те же модели
в разных режимах: `gemini-3.7-flash-low`, `-medium`, `-high` — одна модель.
Поэтому в списке остаются сами модели, а уровень вынесен в отдельный
переключатель рядом. Где выбора нет, переключатель скрыт.

Псевдонимы (`agy`, `gpt-4o` и прочие) из списка убраны — они ведут на те же
модели. Сохранённый ранее псевдоним переводится на настоящее имя при запуске.

## Обновления

Приложение раз в запуск смотрит, нет ли нового выпуска в GitHub, и предлагает
обновиться. Скачанный установщик проверяется по контрольной сумме: она лежит
в выпуске отдельным файлом `*.msi.sha256`. Не сошлась — установка не начнётся.

Если сборки раздаются иначе, в `%APPDATA%\GeminiDesktop\settings.json` можно
добавить строку:

```json
"updateUrl": "https://ваш.шлюз/up"
```

Тогда приложение будет спрашивать про обновления этот адрес. В окне настроек
такого поля нет намеренно: случайно сменить источник обновлений не должно быть
легко.

## Сборка из исходников

Нужен Python 3.11+ и Windows.

```powershell
python -m venv .venv
.venv\Scripts\pip install pywebview pyinstaller
.venv\Scripts\python.exe app.py
```

Собрать exe:

```powershell
.venv\Scripts\pyinstaller.exe --noconfirm "Gemini Desktop.spec"
```

Собирать нужно **именно** интерпретатором из `.venv`. Системный Python обычно
без `pywebview`, и PyInstaller соберёт exe без него: файл получится заметно
меньше обычного (около 16 МБ вместо ~20) и при запуске ничего не покажет.

Собрать установщик (нужен [WiX 6](https://wixtoolset.org/)):

```powershell
powershell -File installer\build_msi.ps1
```

Версия берётся из `APP_VERSION` в `app.py`, чтобы она не разъезжалась
с тем, что видит проверка обновлений. Скрипт печатает и контрольную сумму —
её же нужно приложить к выпуску файлом `GeminiDesktop-<версия>.msi.sha256`.

`make_icon.py` пересобирает `icon.ico` из `assets/spark.png`.

## Как устроено

```
app.py            бэкенд: запросы к шлюзу, инструменты, хранилище, мост в JS
ui/index.html     разметка окна
ui/style.css      оформление
ui/app.js         интерфейс: чаты, настройки, вложения, обновления
installer/        WiX-описание установщика и скрипт сборки
make_icon.py      сборка иконки
assets/           исходник иконки
```

Питон и интерфейс общаются через мост pywebview: JS зовёт методы класса `Api`,
Python шлёт события обратно. Окно хранится только в поле с подчёркиванием
(`api._window`) — pywebview обходит поля `js_api` при старте, и обычное поле
с окном внутри подвешивает запуск.

Копия приложения всегда одна. Крестик прячет окно в трей, процесс живёт
дальше; если после этого запустить ярлык, новая копия увидит именованный
замок ядра, постучится в сокет работающей, та покажет окно — и новая уйдёт.
